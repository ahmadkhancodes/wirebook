# Wirebook pre-launch review (M5, 7 Nov 2026)

Scope: data correctness, tenant isolation, security, billing, public claims, accessibility, ops. I read the code; I did not rely on PROGRESS. Everything still runs against the Web Connector simulator only. Real QuickBooks remains the biggest open risk (MANUAL_STEPS 6).

Each finding gives the file and line, the failure scenario, and the fix. **Fixed** means it was fixed in this task, with a test in `tests/unit/m5-review.test.ts` (or `tests/e2e`) that fails on the old code and passes now. Line numbers refer to the code after this task.

## P1: should fix soon

Fixed in this task (small and safe):
- **API keys: admins could not create keys.** `src/lib/auth/roles.ts`. Better Auth's api-key plugin checks `apiKey:create/update/delete`, but our roles only granted `read`/`manage`. Admins saw the button and got a 403; only the org creator worked. The statements are added for owner and admin. Test added.
- **Webhook SSRF through DNS.** `src/lib/webhooks/outbound.ts:65`. `isSafeWebhookUrl` checked only the literal host, so a public name resolving to `127.0.0.1` or `169.254.169.254` passed. Every delivery now resolves the host and refuses private, loopback, link-local, CGNAT and unique-local addresses (`blocked_address`). A DNS-rebinding race between the lookup and `fetch` remains (P2).
- **Late replies.** `src/lib/qbwc/handler.ts:169`. A reply whose `requestID` is not the in-flight job's id (a late answer from a dead session) is ignored instead of completing the wrong request.
- **Connection errors.** `src/lib/qbwc/handler.ts:202`. `connectionError` marked an in-flight **write** from an earlier session as `failed`, though QuickBooks may have applied it. A retry with a new key would then duplicate it. Writes now become `outcome_unknown`; reads stay `failed`.
- **Upgrade quantity.** `src/app/api/stripe/webhook/route.ts`. The Stripe quantity was synced only when a new file became active, so an org upgrading with 3 active files was billed for 1 until a 4th appeared. Every relevant Stripe event now runs `syncStripeQuantity`, which is a no-op when Stripe already matches.
- **Health check.** `src/app/api/health/route.ts` now pings Mongo with a 2 s budget and returns 503 when it is down. Mongo client timeouts were tightened (`connectTimeoutMS` 5 s, `socketTimeoutMS` 20 s, server selection 5 s) in `src/lib/db/mongo.ts`.
- **Connect page.** `src/app/connect/[token]/connect-steps.tsx`. An expired or used link showed "We lost touch… Reconnecting" forever; a 404 or 410 now reloads into the server-rendered state. A polite live region announces step progress.
- **Dark danger button contrast.** White on `#ff8a80` was 2.3:1. A new `--danger-text` token (`#2a1614` in dark) gives 7.5:1 (`src/app/globals.css`, `src/components/ui/button.tsx`).
- **Reduced motion** now also zeroes transitions.
- **Copy:** webhooks are shipped but the copy called them "roadmap" (`compare.ts:38`, landing "Coming in v1", Starter Pack highlight). The connect link is valid 24 h, not 7 days (`connect-flow.ts:12`, landing). The landing snippet showed a non-existent `POST /v1/end-users`. "QuickBooks Desktop 2024 is fully supported" now says it has been validated against the simulator, with the real run pending.

Open:
- **(open) Stripe quantity at month rollover.** `src/lib/billing/metering.ts:121`. The calendar-month meter resets on the 1st. The first sync of the month sets the Stripe quantity to 1 (a proration credit), and later syncs step it back up (proration charges). The net is roughly right when files sync early in the month, but invoices are noisy and depend on timing. Fix: report the previous month's active-file count once at the period boundary (cron), or move to Stripe metered usage. Needs a real Stripe sandbox run (MANUAL_STEPS 1).
- **(open, needs a design and a schema change) No way to revoke a company file.** No API or dashboard action disables an end user or rotates its Web Connector password. The password is derived from the end user id, so a reconnect link shows the same one. Fix: `DELETE /v1/end-users/{id}` (or disable), which blanks `qbwcPasswordHash` and fails queued jobs; add a password version to the derivation.
- **Suspension (fixed).** `suspendedRefusal` in `abuse.ts` now runs in the `admit` hook; test added. Was: an admin-suspended org or key stops the REST API only. The Web Connector still drains already-queued jobs. Fix: check `org_settings.suspended` in the `admit` hook.
- **(open, product decision) Plan downgrade mid-month.** A Production org that downgrades to Developer keeps all of this month's active files usable, since `active.includes(id)` lets them through. The cap applies again next month.
- **(open, owner decision) SDK package names.** `@wirebook/sdk` and `wirebook` in code and docs, against `@buffersol/wirebook` and `buffersol-wirebook` in MANUAL_STEPS 5. `src/content/docs/sdks.ts` says unpublished but shows `npm install`. Pick one name before publishing.
- **"$0 for 2 months" migration offer (fixed, copy).** Copy now says to write to us for a free migration period. Was: `pricing/page.tsx:23`, `billing.ts:30`. There is no mechanism; it is applied by hand on request. Say "contact us" or build a coupon.
- **Mail in production without a provider (fixed).** `transportFromEnv` throws in production unless `MAIL_PROVIDER=console` is explicit; test added. Was: It falls back to the console transport: no link leaks, but nobody can sign in. Fix: fail loudly (503 plus log) in production.
- **Env docs.** No single table lists the required production vars (`BETTER_AUTH_SECRET`, `CRON_SECRET`, `MONGODB_URI`, `MONGODB_DB`, `STRIPE_WEBHOOK_SECRET`, `MAIL_FROM`, `ADMIN_EMAILS`). Added to MANUAL_STEPS.
- **(open, UI sweep, not touched here) Accessibility.** Delete-key buttons have no per-row accessible name (`api-keys-client.tsx`). The request-log time link's `aria-label` does not contain its visible text (WCAG 2.5.3). `Button size="sm"` is 32 px and the environment switcher about 28 px, both under 44 px at 375 px. `aria-selected` on a `<tr>` should be `aria-current`.

## Checked and fine

- **Tenant isolation.** Every REST path resolves the end user and the request through `projectIdOf(auth)` (`engine.ts`). `GET /v1/requests/{id}` checks `meta.projectId`. Dashboard routes use `ownsUser(org)` and `${org.id}__${env}`, webhook routes and deliveries are scoped by `orgId`, and cursors are bound to object and end user. Tickets are bound to one end user.
- **API keys.** Hashed by Better Auth. The environment comes from server-side key metadata, and a missing value means test. Revoked keys fail `verifyApiKey`. Org membership and role are checked by the plugin.
- **XML.** fast-xml-parser 5.12 refuses external entities (no XXE) and nested entity expansion; checked with a billion-laughs payload. `/qbwc` caps the body at 5 MB, REST at 1 MB.
- **Web Connector auth.** scrypt hashes with `timingSafeEqual`, lockout after 20 failures an hour, and an unknown ticket ends the session instead of faulting.
- **Stripe webhook.** Signature on the raw body, event id recorded after success, entitlement recomputed from Stripe (order independent), other apps' customers and subscriptions ignored. Checkout takes the plan from an enum, and no client flag grants a plan.
- **Outbound webhooks.** HMAC `t.body` signing, 8 attempts, `redirect: manual`, 10 s timeout, payloads carry ids and statuses only (no QuickBooks data), the secret is shown once.
- **Logs.** Error logs carry messages and paths only, no request bodies.
- **CSRF.** Origin check on cookie-authenticated state changes (`withApi`); API-key requests are exempt by design.

## Launch hardening (10 Nov 2026)

Status of the P1s that were open above, plus the money and mail checks. Tests: `tests/unit/hardening.test.ts` and the "launch hardening" block in `tests/unit/billing.test.ts`; both failed on the old code.

- **Company file revoke: fixed.** `DELETE /v1/end-users/{id}` and the dashboard button "Revoke company file" call `revokeEndUser` (`src/lib/connect/index.ts`): sets `revokedAt`, `authenticate` answers `nvu`, open sessions end, queued requests fail with the new `end_user_revoked` error, connect links are refused. Idempotent; an already sent request is left to finish.
- **SDK names: fixed (decision).** `@wirebook/sdk` and `wirebook`, as in code and docs. MANUAL_STEPS item 5 now matches.
- **Accessibility sweep: fixed.** Per-row delete-key labels, request-log time link label contains its visible text, `aria-current` instead of `aria-selected` on rows, `Button size="sm"` and the environment switcher are 44 px high below the `sm` breakpoint.
- **Compare source line: fixed.** The page names the brief tab and says webhooks and SOC 2 rest on Apideck alone.
- **Plan downgrade mid-month: closed by decision** (DECISIONS). The meter is per calendar month; files already active stay usable until the month ends and the cap applies again from the 1st.
- **Stripe quantity at month rollover: still open, needs the owner.** The fix changes how invoices are computed (anniversary billing period against the calendar-month meter) and can only be validated with a real Stripe sandbox subscription across a renewal (MANUAL_STEPS 1). Current behaviour is correct in total but noisy in proration lines.
- **Money paths, checked.** Entitlement is recomputed from Stripe on every `customer.subscription.*`, `invoice.*`, `checkout.session.completed` and `charge.refunded`, so order and duplicates cannot grant or revoke wrongly; the event id is recorded only after success (a failed run returns 500 and Stripe retries). Unknown events answer 200, are recorded and logged (`stripe_event_ignored`); events for unknown customers answer 200. A plan never depends on the checkout redirect, only on the webhook. New: a full refund leaves a `refund:<payment_intent>` marker so a late `payment_intent.succeeded` cannot re-grant a refunded payment (no lifetime plan exists today, so this is defensive).
- **Mail when Resend rejects: fixed.** The magic link, invitation and broken-connection emails go through `sendMailSafe`: a bad address, 4xx/5xx, rate limit or network failure is logged with a scrubbed code, the request answers normally (the magic-link response stays identical for every address, which also prevents enumeration) and no provider text reaches the client. `healthTick` no longer aborts on a failed send and does not retry the same incident every minute. Consequence: with no mail provider in production a sign-in silently sends nothing; watch the `mail_send_failed` log line.
