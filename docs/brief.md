- Category: B2B developer API / integration infrastructure for QuickBooks Desktop (Pro/Premier/Enterprise, Windows).

## Problem & promise
- Problem: QuickBooks Desktop has no cloud API. Software teams must host a SOAP server for the Windows-only Web Connector, speak order-sensitive qbXML, handle opaque errors (e.g. 0x80040400), and support customers' Windows machines.
- Promise: "QuickBooks Desktop, as a normal API." Your app makes a normal API call; Wirebook handles the Web Connector. REST + typed TS/Python SDKs (C# in v1), a connect flow customers can finish alone, unified errors with fix guides, at $24.99 per company file.
- Workbook's gaps vs leader: price ($49/file steep for SMB vertical SaaS with $50-150 ARPU; no published volume/annual price); no C#/Java/PHP SDK; no webhooks (per Apideck comparison); leader founder attention split (now co-founder of Dispatch, YC P26) and business is for sale.

## MVP scope (priority order; P0 = MVP, P1 = v1, P2 = later)
Roadmap order: infra foundation -> mail + observability -> Windows rig + SOAP bridge -> qbXML codec + queue -> core objects -> errors + connect flow -> dashboard + auth -> SDKs + docs -> objects batch 2 + billing -> private beta/launch.
1. Hosted Web Connector SOAP bridge + per-file serial queue (FR-07/08/09, tab 12). AC: Web Connector authenticates and exchanges a CustomerQuery; GET /customers returns JSON via queue in <5 s warm. Implement authenticate, sendRequestXML, receiveResponseXML, connectionError, getLastError, closeConnection, clientVersion, serverVersion; percent <100 while jobs remain; unknown ticket ends session (never fault); HTTPS only; adaptive RunEveryNSeconds.
2. qbXML codec generated from Intuit XSD (16.0, downgrade to version reported) - never string concatenation (FR-14). AC: fixture tests for every endpoint pass on QB 2024 R-release. Mod requests carry EditSequence (exposed as revisionNumber). Check statusCode (1 = empty OK, 3100 edition not supported, 3140 invalid reference).
3. REST/JSON for ~40 core objects (FR-11): customers, vendors, employees, items (all types), accounts, classes, terms, invoices, estimates, sales orders, sales receipts, credit memos, receive payments, bills, bill payments, checks, deposits, journal entries, purchase orders, company info. AC: list/retrieve/create/update tested against sample company files. Base /v1/qbd/{object}; Bearer sk_ key + X-End-User-Id header.
4. Raw qbXML passthrough (FR-12). AC: any valid qbXML returns raw response plus parsed JSON when possible.
5. Request validation, idempotency, pagination, concurrency (FR-13, 15-19): invalid field -> 400 with JSON path; Idempotency-Key on writes with 7-day retention (replay returns original, different body 409); cursor pagination {data,nextCursor,hasMore,cursorExpiresAt} with expired cursor -> 410; filters map to native qbXML filters; revisionNumber stale -> 409; sync wait up to 90 s or Prefer: respond-async.
6. Unified error object + deterministic error catalogue (FR-22/23/44): type, code, message, userFacingMessage, guideUrl, httpStatusCode, integrationCode, retryable, requestId. 30 codes/guides at MVP (80 in v1). No AI model; same input -> same message. Lifecycle states queued/sent/succeeded/failed/outcome_unknown (FR-24).
7. Hosted 4-step end-user connect flow + .qwc generator (FR-05..09). AC: each step turns green only when server observed it; two end users never share OwnerID/FileID; non-technical tester connects in <10 min unaided; connect link valid 7 days.

## Core user flow (first run to "aha")
Developer onboarding: 1) Sign up (email + invisible ALTCHA, magic link, optional passkey) -> org + Test/Production projects auto-created. 2) Get-started checklist: "Create secret key" (sk_test_..., shown once). 3) Create end user (name, own app's ID) -> connect session URL valid 7 days. 4) Quickstart: run SDK snippet against sample company file -> queued, delivered on next Web Connector poll, JSON returned (202 'queued' + guide link after 30 s if connector not running).
End-user connect (bookkeeper on QuickBooks PC): 1) Welcome - detects Windows, explains 4 steps (Mac/phone -> "open on the QuickBooks computer" + email-me-link). 2) Download .qwc (unique OwnerID/FileID). 3) Open .qwc, choose "Yes, always allow access even if QuickBooks isn't running"; live waiting state. 4) Paste password into Web Connector, tick auto-run -> first session reads company info + QB version -> status Connected.
Core job (create invoice): POST /v1/qbd/invoices with Idempotency-Key -> validated, translated to ordered qbXML, queued per file -> await sync (<=90 s) or Prefer: respond-async -> inspect Request detail timeline (queued, sent, QB status code, duration, response). Timeout after send -> outcome_unknown, reconcile by RefNumber query before retry.
"Aha": first successful request against sample file within ~15 min, shown in request log with green tick.
Then: switch to Production -> hosted checkout -> first real file billable on first successful data request -> upgrade to Starter Pack/annual. Cancel: cancel at period end, CSV export of logs/end users, re-subscribe within 30 days restores credentials. Broken connection recovery: red status -> likely cause + "send fix email" -> next successful poll flips to Connected + `connection.recovered` webhook; machine off for weekend shows "Asleep" after 6 h, not "Broken".

## Design direction (from tabs 19-21; workbook-provided, not inferred)
